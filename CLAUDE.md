# Scores

Ad-free live scores, standings, rankings, box scores and team pages for NFL, NBA, MLB, NHL, NCAAF, NCAAM, WNBA, MLS, Premier League and Champions League. A static single-page app (no build step, no runtime dependencies, no backend) that reads ESPN's public JSON feeds straight from the browser, wrapped as the iPhone app "Phade Scores" for TestFlight (see "iOS app" below). Owner: Mike (HarkDigital).

## Run, test, deploy

```
npm start   # serves the folder at http://localhost:8080 (npx serve)
npm test    # node --test, unit tests for the data layer (Node 18+)
```

- ES modules, so open it through a server, never `index.html` from disk.
- **Deploy = merge to `main`.** GitHub Pages serves `main` from the repo root (`.nojekyll` keeps Jekyll out) at https://harkdigital.github.io/score-app/. Every push to `main` triggers a "pages build and deployment" run (about a minute). Pages settings can't be changed from a cloud session; Mike flips those himself.
- Work on a branch, open a PR to `main`, merge when done. Mike merges or asks Claude to.

## ESPN feeds and their quirks (all learned the hard way)

The feeds are unofficial and undocumented. Before changing a parser, check the shape against a real response, not memory.

- **Endpoints**: scoreboard `site.api.espn.com/apis/site/v2/sports/{path}/scoreboard`; standings `.../apis/v2/sports/{path}/standings` (the `/apis/site/v2` standings path returns only a link); polls `.../apis/site/v2/sports/{path}/rankings`; box score `.../summary?event={id}`; team schedule `.../teams/{id}/schedule`.
- **CORS**: scoreboard, standings, rankings, summary and team schedule send `Access-Control-Allow-Origin: *`. The bulk `/teams` list does NOT, so the team picker builds its list from standings (`teamsFromStandings`). Never fetch `/teams` from the browser.
- **Host fallback**: `site.api.espn.com` sometimes answers 403 with no CORS header (looks like a network error). `getJson` retries once on `site.web.api.espn.com`, which serves the same feeds. Don't add custom request headers (ESPN doesn't answer the CORS preflight).
- **Scoreboard `dates=`** takes one day (`YYYYMMDD`). A range (`dates=A-B`) answers 400 on both hosts (since about Oct 2026).
- **College `groups=`**: scoreboard uses `groups=80` (FBS) and `groups=50` (D-I) with a `limit` (keep it at 500 or below: above that ESPN silently serves its default 25 games); standings use `group=80` / `group=50`. FCS is `81`. A conference id as `groups` gives every game one of its teams plays (non-conference too); NO `groups` at all is ESPN's Top 25 board (games with a ranked team). `standings?group={conference}` is that conference alone (~300 KB vs ~2.5 MB for a division; ~70 KB gzipped). The conference ids are hardcoded in `cfbFilters()` (`espn.js`) because the list feed, `scoreboard/conferences?groups=80|81`, sends no CORS header; re-check it after realignment. NCAAF's `divisions: ['80', '81']` makes My Teams (`dayUrls` + `mergeGames`), the push server's watcher and the team picker (`teamListUrls`) read both FBS and FCS. The rankings feed's `fcs` poll is shown (after the FBS polls); `afca` (Division II/III) is not.
- **NFL, MLB, NBA and NHL standings** come by division (`standingsParams: { level: '3' }`: conferences (MLB: leagues, `isConference` unset) each with division tables; `level=2` would be conference tables). `parseStandings` treats a table two levels down as a division of its parent (`conference`), and shortens "American League East" to "AL East" and "Atlantic Division" to "Atlantic". `standingsView(standings, view, rules)` builds Division (default), Conference (MLB: League; by record, NHL by points) and Playoff Picture from that one download; `rules` is the league's `standingsViews` in `LEAGUES`: `divisions` (NFL `wildCards: 3, byes: 1`; MLB `wildCards: 3, byes: 2`: division leaders seeded first by record, whatever a wild card's record, then the wild cards), `seeds` (NBA: 1 to 6 Playoffs, 7 to 10 Play-In, divisions don't count) and `divisionTop` (NHL: the top 3 of each division labelled A1..M3, then WC1/WC2 by points). Every entry's `playoffSeed` is its CONFERENCE seed with the league's tiebreakers (and, after the NBA's play-in, its result: 42-40 POR seeded 7th over 45-37 PHX); ESPN's order is used when every team has its own seed (`seeded`), else the record, as early in a season many teams share a seed. Tested against 2025-26 and 2026 final standings: the picture's teams are exactly the ones ESPN marks clinched. Clinch marks are explained for the NFL only (`*` division and bye, `z` division, `y` wild card, `x` playoff spot, `e` eliminated); the other leagues' letters (NBA `xp`, `pb`...) are shown unexplained.
- **Standings**: entries arrive in no useful order; sort by `rank` (soccer), else `playoffSeed` (pro), else the table's sort stat (college: `leagueWinPercent`, the conference win %). College entries repeat every stat once per split under the SAME `name`; split copies have an underscore in `type` (`vsconf_wins`), so only read stats whose `type` has no underscore. Conference record is the record stat with `type: "vsconf"`, overall is `type: "total"`. Soccer zone notes carry `{color: "#81D6AC", description}`. College basketball standings are a ~6 MB download.
- **Team colors** are bare hex without `#` ("e31837", sometimes uppercase); `teamColor()` normalizes and rejects anything else.
- **Lines**: `competitions[0].odds[]` on upcoming games only (gone after kickoff and on finals). Prefer a real book (DraftKings); skip projection models (`numberfire`, `teamrankings`), whose "odds" are win percentages; `consensus` only as a fallback. `spread` is from the home side; `details` is ESPN's wording ("KC -3.5", "EVEN"). A price must read as American odds (|n| >= 100 or EVEN).
- **Summaries** are 0.5 to 1.7 MB: fetch only when a game is opened; a live game page refreshes the summary every 30s and checks its score and clock every 5s on the day's scoreboard (`quick` in `pages.js`, run at once the first time: it keeps the scoreboard entry as `page.live` and re-renders (patched) when the clock, the ball's spot, the down or possession changes; a score or state change loads the summary at once). The summary has no ball spot, so a live football game page draws its field (`fieldHtml`, positions from `espn.js` `fieldView`) from `page.live`. ESPN caches the scoreboard 1s and summaries 4s, so 5s polls are fresh. Football scoring comes from `scoringPlays`, hockey from `plays` with `scoringPlay`, soccer from `keyEvents` (goals and red cards). Baseball and basketball get no scoring list (every pitch or basket is a "scoring play"). Baseball R/H/E come from header competitors' `hits`/`errors`; MLB team stats are grouped objects, so there is no team-stat comparison for baseball. Soccer period scores are garbled past full time (-1s, halves that don't add up), so soccer shows a line score only for a 2-period game.
- **Team schedules** return ONE season type per request and only the current one by default (an empty list between seasons): request `seasontype=2` and `seasontype=3` and merge by event id. Soccer splits results (default) from fixtures (`?fixture=true`): request both. Schedule competitors have `score` as an object (`{value, displayValue}`) and `logos[]` instead of `logo`; `parseGame` handles both shapes.
- **News**: `.../apis/site/v2/sports/{path}/news?limit=` (CORS ok), and `&team={id}` for a team (`/teams/{id}/news` answers an empty object). A team's feed is every article that TAGS the team in `categories` (`type: "team"`, `teamId`), so power rankings, fantasy and draft-order round-ups tagging 10 to 32 teams come along: `parseNews(data, {teamId})` keeps an article only when it tags the team and at most one other (a game's preview or recap tags both); college tags each school twice (team and university) under one `teamId`, so count distinct ids. That keeps roughly 15 to 30 of a team's last 50. My Teams' News (`fetchMyNews` in `app.js`) reads each followed team's feed (50 each for up to 3 teams, else 25) and `mergeNews` puts them together newest first, tagging each article with its followed teams (`teams`, drawn as logo + abbreviation) and keeping a story in two teams' feeds once; a team whose feed fails is listed in the status line like My Teams' scores. Types: `HeadlineNews`/`Story` (articles), `Media` (video), `Recap`, `Preview`; previews and recaps link over plain `http://www.espn.com/...` (upgraded to https). Some listed photos are gone (404): the page drops a news photo that fails (`failedImages`, the `error` listener in `app.js`). Photos run up to 1920px; ESPN's resizer crops them to size (`newsImage`: `a.espncdn.com/combiner/i?img=/photo/...&w=&h=&scale=crop`); video thumbnails (`espnmedia-cdn.akamaized.net`) don't go through it.
- **Team stats** (`stats.js`): from the CORE API, `sports.core.api.espn.com/v2/sports/{sport}/leagues/{league}/seasons/{year}/types/{type}/teams/{id}/statistics` (CORS ok): `splits.categories[].stats[]` with `displayValue` and a league rank (`rankDisplayValue`, "Tied-23rd", shown "T-23rd"; soccer has none). NOT the site API's `/teams/{id}/statistics`, which serves whatever phase is current (an MLB team's postseason only, a basketball team's last season while its season block says "Preseason") and ignores `season`/`seasontype`. The year comes from the team schedule (`parseSchedule` `seasonYear`, its `requestedSeason`: off-season captures show a current season of 2025 but a requested 2026); `statsSeasons` tries that year's regular season (type 2; soccer type 1), then the year before, as a season with no games answers 404. Per-game averages (`avgPoints`) carry no rank, so the key stat takes its total's (`rankFrom`). Percentages come as bare numbers ("44.00", shown "44.0%"); save percentage is a fraction (".909"). Placeholders the feed fills with zeros (ratings, WAR, per-48 averages, qualification flags) are left out of All stats. College football has no red zone numbers (every team 0.00) and doesn't rank 3rd-down rate (every team Tied-1st), so it gets its own key list. Points and yards ALLOWED are 0 for every team (`defensive.pointsAllowed`), so defense shows takeaways and sacks. The team page loads stats when the Stats tab opens (`loadStats` in `pages.js`).
- **Playoff series** (MLB, NBA, NHL): a competition's `series`. The scoreboard's is the playoff series itself (`type: "playoff"`, `summary` "LAD lead series 2-1", `totalCompetitions` = best of, `competitors[].wins`); a summary header's is a LIST (`current`, `season` = the regular season's head-to-head "ATL wins series 5-1", `playoff`, the last two with `events[]` ids in order), so `seriesOf` (`espn.js`) picks `type: "playoff"`. The round and game number are the summary's `header.gameNote` ("NLDS - Game 3"; the scoreboard's `notes[0].headline`). Game page: `seriesHtml` (wins as dots toward `ceil(bestOf / 2)`, links to the series' games); scoreboard cards add the summary to the note line.
- **Baseball's diamond**: the scoreboard's live `situation` has `onFirst`/`onSecond`/`onThird`, `outs`, `balls`, `strikes`, and `batter`/`pitcher` (`athlete.shortName`, `summary`: the day's line); `parseGame` keeps it as `diamond` (`diamondOf`; null without numeric `outs`, so other sports never get one). The game page draws it (`diamondHtml`, from `page.live` like the football field); the Lock Screen card gets `bases` ("13" = first and third, a string so the server's change check stays a plain compare), `outs`, `balls`, `strikes` through `cardSituation` (iPhone build 15: `DiamondView`/`OutsView` under the inning; Android shows ESPN's "2 outs · On 1st, 3rd" text).
- **LineSteam links**: leagues with a `linesteam` slug in `LEAGUES` (nfl, nba, mlb, nhl, ncaaf→`cfb`) get LineSteam's mark (`icons/linesteam-mark.png`, from LineSteam's `branding/generated/mark-transparent.png`) as a 36px circle top right of the game page's matchup card, linking to `https://linesteam.com/espn/{slug}/{espnEventId}` (`lineSteamUrl`). That route lives in LineSteam (Mike's "Odds movement tracker" project, deployed with its `deploy/deploy.sh`): its poller matches games to ESPN's scoreboard every 3h and the route redirects to the game, or to the league dashboard when unmatched.
- **Football** is browsed by week using the scoreboard's `leagues[0].calendar` (entries carry `label`, `detail` like "Sep 9-15", season type label). Other sports by day. My Teams fetches football by date (`byDate`).

## Verifying in a browser

- Cloud sessions can't reach ESPN (or its logo CDN) through the egress proxy. To see the UI, drive the app with Playwright (preinstalled at `$(npm root -g)/playwright`) and answer ESPN requests from fixtures with `context.route`. Serve the app itself through `route` too (Chromium there sends even localhost through the proxy), and fetch Google Fonts with Node and fulfill them (Chromium doesn't trust the proxy CA; never disable TLS checks).
- Without the CDN, logos render as the team-color fallback badges; real logos load on a device.
- On a Mac, `npm start` and a normal browser just work against live ESPN.
- **Gestures need the iOS Simulator** (the browser pane sends mouse events, not touches). Serve the folder (`npx serve -l <port> .`; 8080 is sometimes already taken, and `serve` then silently picks another port, so read its output), run `npm run ios:sync`, then point `ios/App/App/capacitor.config.json` (gitignored) at `http://localhost:<port>/` with `allowNavigation: ["localhost"]`, build the `App` scheme for a simulator and drive it with touch paths. Edge swipes must start within 4pt of the screen edge. WKWebView caches the scripts, so after editing them kill and relaunch the app (and check the serve log shows the new requests). Run `npm run ios:sync` afterwards to put the live URL back.

## Navigation and state

- Hash routes: `#/game/{leagueId}/{eventId}` and `#/team/{leagueId}/{teamId}`, rendered by `pages.js` over the scoreboard. In-app links push history entries with a `depth`; the header back button goes back within the app, or to the scoreboard when the page was opened from a shared link. The scoreboard pauses polling while a page is open and restores its scroll on return.
- Refresh cadence: live 5s, kickoff within 30 min 30s, later today 5 min, otherwise none; polling stops while the app is hidden.
- **Self-update** (`update.js`): the iPhone app keeps the page loaded for days. GitHub Pages stamps every file of a deploy with the same `Last-Modified` (and `max-age=600`); 3s after launch and whenever the page comes back to the front (at most every 5 min) it HEADs the page with `cache: 'no-store'`, and if that stamp is newer than `document.lastModified` it re-fetches its own JS/CSS with `cache: 'reload'` (from `performance` resource entries) and reloads. `sessionStorage` `scores.reloadedFor` stops loops. `npx serve` sends no `Last-Modified`, so it's inert locally; test it with `python3 -m http.server` and `touch index.html`.
- **Back and forward**: `pages.js` keeps the last 8 pages' data (`recent`), so going back renders at once and refetches only if older than 10s. `navigate()` saves the scroll of the entry it leaves in `history.state.scroll`, and `applyRoute` restores it when the page rendered from cache. In the iPhone app the edge swipes are WebKit's own (`allowsBackForwardNavigationGestures`), walking these same pushState entries with snapshots. Swipes that start more than 24px from a side are `swipe.js` (app only, `inApp()`): the content follows the finger, past 30% of the width or a flick commits, it slides out, calls `goBack()`/`history.forward()` and slides the next view in. WebKit lets only the FIRST `touchmove` cancel the page's scroll, so both `swipe.js` and `pull.js` decide on the first move; if a held sideways swipe turns vertical, `swipe.js` scrolls the page by hand. `app.js` tracks `depth`/`furthest` so a forward swipe only moves when there is a forward entry.
- **Pull to refresh** (`pull.js`): touch only, starts only at `scrollY` 0, claims the gesture on the first move if it's straight down (then `preventDefault`s the moves), and ignores touches that begin within 24px of a side (the native swipes) or inside anything that scrolls sideways (league pills, tables). `html, body { overscroll-behavior-y: contain }` already kills the rubber band, so there is no bounce to fight. It calls the same refresh as the header button and waits for it.
- **Team search** (the header's magnifier, `openSearch` in `app.js`): loads every league's team list at once through `teamsFor()`, the same session cache the team picker uses (standings, so NCAAM is the big one), and ranks matches with `searchTeams` (`standings.js`, tested): exact abbreviation, then a word start, then anywhere, in `LEAGUES` order. The input is focused inside the tap or iOS won't show the keyboard.
- **Haptics**: `haptic(style)` in `native.js` asks the app (bridge action `haptic`, `Haptics` in `NativeBridge.swift`; builds before 7 ignore it). One capture-phase click listener in `app.js` sends `selection` for `[role="tab"]`, `.day` and `[data-poll]` buttons and `light` for every other button; the NCAAF filter's change sends `selection`, and `pull.js` sends `medium` as the pull arms. Links (game cards, team rows) don't buzz.
- Hover styles that change a tapped control's look go inside `@media (hover: hover)`: iOS keeps `:hover` on the last thing tapped.
- `localStorage` keys: `scores.league` (last tab), `scores.myTeams` (followed teams `{league, id, name, abbr, logo, color}`), `scores.filters` (the last filter per league, `{ncaaf: '8'}`; unknown ids fall back to All FBS). Wrap every storage access in try/catch.
- Chrome (tabs, mode switch, day strip) re-renders only when its inputs change, so a refresh never steals focus or scroll. The "Updated" line (`#status`) sits under the content, as on the game and team pages; sub filters (the NFL's standings views, the polls) are centered (`.toolbar-center`).
- The scoreboard and the game and team pages are drawn with `patchHtml` (`ui.js`), not `innerHTML`: it matches the new markup to the old nodes by position and tag and touches only what changed. Replacing the markup made every logo a new `<img>`, and WebKit shows a new image blank until it decodes, so the logos flashed on every 5s refresh in the iPhone app. A `<details>` keeps the open state the person gave it.

## iOS app ("Phade Scores", TestFlight)

- A thin Capacitor 8 shell (`ios/`, Swift Package Manager, no CocoaPods) that loads the live Pages site: `capacitor.config.json` sets `server.url` to `https://harkdigital.github.io/score-app/`. Capacitor iOS loads the full URL including the path (`appStartServerURL`). Bundle ID `digital.hark.scores`, Phade's team (`DEVELOPMENT_TEAM = 72U2ZL3GVM`, automatic signing), display name "Phade Scores", iPhone and iPad (`TARGETED_DEVICE_FAMILY = "1,2"`, keep all four iPad orientations or App Store validation fails).
- **Web changes ship by merging to `main`**, no new build. A new TestFlight build is only for native changes (icon, splash, name, `Info.plist`, `capacitor.config.json`, Swift); raise the build number with `npm run ios:bump` before every upload (the App and LiveGame targets must match or the upload fails). Mike's step-by-step is in README.md ("iPhone app (TestFlight)").
- **Minimum iOS 16.0** (LiveGame extension 16.2). The Capacitor CLI writes `CapApp-SPM/Package.swift`'s platform from the FIRST `IPHONEOS_DEPLOYMENT_TARGET` in project.pbxproj, so keep every target at 16.x or `ios:sync` flips it.
- **No Capacitor plugins and no Capacitor JS in the web app** (it has no bundler). `SceneDelegate` starts `ViewController` (`ios/App/App/ViewController.swift`, a `CAPBridgeViewController` subclass): it turns on WebKit's back/forward edge swipes, installs the `phadeScores` message handler (`NativeBridge.swift`, `WKScriptMessageHandlerWithReply`, answers only the app's own host in the main frame; `native.js` calls it), hands remote notifications to `PushManager` through Capacitor's `notificationRouter.pushNotificationHandler`, and opens `phadescores://game/{league}/{id}` (the card's tap) and alert taps (`route` in the payload) by setting the web app's hash. The route waits in `pendingRoute` until the page answers that its hash is the route, and is handed over again after every load (KVO on `isLoading`): iOS closes a backgrounded app's web page, Capacitor reloads it on the way back, and a hash set on the old page was lost, so news alerts tapped hours later opened the scoreboard. A tap that launches the app comes through `SceneDelegate` (`connectionOptions.notificationResponse`), since Capacitor only becomes the notification delegate as the scene connects. Both apps inject the same snippet: a hash already equal to the route is announced again (a synthetic `hashchange`), so a team page showing another tab still turns to News. The offline page's Try again uses `location.replace` so a back swipe can never land on it. The shell's look is plain `Info.plist`: `UIStatusBarStyle` = `UIStatusBarStyleLightContent` (CAPBridgeViewController reads it), `UIUserInterfaceStyle` = `Dark`, `ITSAppUsesNonExemptEncryption` = false. `ios.contentInset` is `"never"` because the CSS already pads for the safe area (Phade's lesson: `"always"` insets the header twice). `LaunchScreen.storyboard` has a `#0a0a0a` background.
- **`native/www/index.html` is required**: Capacitor refuses to start without a bundled `index.html` even when `server.url` is set, and `server.errorPath` shows the same page when the site can't load (a "Can't reach Scores" page with Try again). `webDir` must never be `.` (it would copy the whole repo, `ios/` included, into the app). `npm run ios:sync` copies it and the config into `ios/App/App/` (both gitignored), so Mike runs it after every pull.
- **Icon and splash** are rendered from `icons/icon.svg` with Playwright and real Poppins (fonts fetched through Node, see "Verifying in a browser"): `AppIcon.appiconset/AppIcon-512@2x.png` is 1024x1024 RGB with no alpha (App Store rule), the three `Splash.imageset` PNGs are 2732x2732 with the rounded icon at 440px on `#0a0a0a`. The web icons in `icons/` come from the same render.
- `cap add ios` and `cap sync ios` run fine on Linux (SPM, no `pod install`); building, signing, archiving and uploading need Mike's Mac and Xcode. `npm audit` flags a moderate `uuid` advisory in the CLI's Xcode-project tooling (dev only, never shipped).
- GitHub Pages also publishes `ios/`, `native/` and `capacitor.config.json` (they're in the repo root). Harmless: a Team ID isn't secret.
- **Lock Screen card** = a Live Activity: `ios/App/Shared/GameAttributes.swift` (in both targets) and the `LiveGame` widget extension (`ios/App/LiveGame/`, bundle `digital.hark.scores.LiveGame`) draw it. The Lock Screen card is a scorebug (`LockScreenView`): each team's logo on a block of its color flush with the card's side, inner edge slanted (`TeamPanel`, `SlantBand`), the scores beside them, `Game.clock` ("8:21 - 2nd" read as "2nd • 8:21") between, live football's timeouts as dashes and a ball for possession, a field strip (`FieldStrip`: end zones in team colors, the left team defending the left goal line, the ball at the spot, the yards to go lit to an amber first-down line; shown for the whole live game so the card's height doesn't change between plays, keep the card under the Lock Screen's 160pt), and a pill row (down and distance or the matchup; LIVE; no league pill, the teams make the sport plain). The Lock Screen card is glass: `activityBackgroundTint` at 30% near-black lets iOS draw its own glass (Liquid Glass on iOS 26+) behind it; an opaque tint turns that off. Logos are ESPN's dark-background versions (`TeamLogos.darkURL`: `/500/` → `/500-dark/`, falling back to the plain one), so a dark mark (the Jets' green wordmark, Iowa's black hawk) shows on its own team color and on the island's black; the saved files carry a `dark-` prefix so builds before it don't mix them up. In the island they also get a soft white glow (`TeamBadge`'s two white shadows, `glow: false` on the card's color blocks). Live football's timeouts, possession and ball spot come from `espn.js` `cardSituation` (scoreboard `situation.homeTimeouts`/`awayTimeouts`/`possession`, and `yardLine`, which counts yards from the HOME team's goal line in the NFL and college alike: NE on its own 37 at Buffalo is 63; `yardLine`/`toGo` only while a team has the ball, as a kickoff's spot has no side; the summary header's `timeoutsUsed` per competitor counts USED timeouts, 3 a half, so the web card reads it only in regulation). A Live Activity can't load web images, so the app saves each ESPN logo (shrunk to 120px PNG) into the App Group `group.digital.hark.scores` (`Shared/TeamLogos.swift` + `App/TeamLogos+Fetch.swift`) before starting a card, when scheduling one, and when the server starts one; the extension reads the file and falls back to the team-color badge. One file per team (`TeamLogos.plainURL`): the cards the server starts carry the scoreboard's `/500/scoreboard/phi.png`, game pages the summary's `/500/phi.png`. iOS draws a server-started card before the app is even running, so when the app then saves a logo that was missing it updates the card with `redraw` counted up (an app-only ContentState key, never pushed): an update with the same content doesn't redraw it, and a pre-game card gets no real update until the start (Oct 2026: a team's first server-started card kept its badges until puck drop). Both targets carry the App Group entitlement (`App/App.entitlements`, `LiveGame/LiveGame.entitlements`). Every unfinished game page has a switch (several cards can be up at once). A game that's on or within 15 minutes of starting goes up from the app (`Activity.request`, `pushType: .token`); a later one is **scheduled**: the app sends the card with its push-to-start token (`pushToStartTokenUpdates`, iOS 17.2+) to `POST /v1/scheduled`, and the server sends Apple a push-to-start 15 minutes before the start (`LOCK_LEAD_MINUTES` in `details.js` and `SCHEDULE_LEAD` in `server/live.js` must match; the watcher times its next fetch for a scheduled card's due time). Before iOS 17.2 (`canSchedule` false) a game within six hours goes up straight away instead (iOS ends a card after 8 hours). `LiveGameManager.begin()` runs in `didFinishLaunching` because iOS launches the app in the background to hand over a remotely started card's own token (`activityUpdates` → `pushTokenUpdates` → `POST /v1/activities`); verified with the app fully quit. **ContentState's and the attributes' keys are a contract** between `details.js` `lockScreenCard`, `server/live.js` (`contentState`, `startPayload`) and `GameAttributes`: change them together (`redraw` is the app's own). The push-to-start payload's `attributes.start` is seconds since 2001 (ActivityKit's default Date decoding), not 1970.
- **Team alerts**: per followed team and per kind (`alerts: {start, score, end, lock, news}` in `scores.myTeams`; an early build's plain `true` reads as starts and finals), set by the switches the team page's bell opens. `lock` = every game on the Lock Screen: the push server starts each of the team's games when a scheduled card would be due (`wantsLock`, `cardFromGame` in `server/live.js`), once per device and game (`sent` mark `token|league:id|lock`, so a swiped-away card stays away), skipping one already up or scheduled from its page. iPhones get a push-to-start to the device's `startToken` (sent with the teams by `PushManager`/`PushServer.registerDevice`; re-sent when the token changes), and `LiveGameManager` ends a server-started card if the same game is already up; Android gets a `start` message with `auto: '1'`, which `LiveCards.start` takes unless the game is up. The row only shows where the app reports `info.teamLockScreen` (iPhone build 12 and Android build 5 on, with push-to-start or Firebase), so older builds never show a switch they can't honor. `news`: the push server reads each wanted team's news every 10 minutes (`checkNews` in `server/watcher.js`, `newsPlan`/`newsPayload` in `server/live.js`; `deploy.sh` ships `news.js` beside `espn.js`): the first look only notes the stories there, then each new story (not videos, recaps or previews) under a day old goes once per device, at most two a look, titled with the team's name from the article's tags; its route is `#/team/{league}/{id}/news`, which opens the News tab (`parseRoute` takes an optional `schedule|stats|news` tab; the apps' route checks allow it from iPhone build 15 and Android versionCode 8). The switch shows where the app reports `info.teamNews` (iPhone build 15 on, whose bridge passes the kind on) or on Android with `teamLockScreen` (Android passes the teams through as they are). Basketball's `score` is the score at each break (end of a quarter or half), every other sport's is every score; the web app sends the list to the app (`setAlertTeams`) at launch and on every change, and `PushManager` registers it with the device token. Entitlement `aps-environment` is in `App/App.entitlements` (Xcode switches it to production on export); debug builds report `sandbox`, release builds `production`.
- **Before the App Store**: privacy manifest and App Privacy answers, 13-inch iPad screenshots, likely "Gambling: Yes" in the age rating because of the betting lines (Phade's 2.3.6 rejection), and guideline 4.2 (thin web wrapper) and 5.2 (ESPN data and team logos are third-party IP) risks. A licensed data provider may be needed for the store version.

## Android app ("Phade Scores", sideloaded APK for testers)

- The same thin Capacitor 8 shell (`android/`, Gradle 8.14.3, AGP 8.13, compile/target SDK 36, min 24) loading the live site through `server.url`, with the iPhone app's native features. No npm plugins and no Capacitor JS in the web app.
- **Bridge**: `NativeBridge` (a native-only Capacitor plugin, registered in `MainActivity` before `super.onCreate`, because plugins load before the page: an `addWebMessageListener` added later misses the first page) gives the page `window.phadeScoresAndroid`, restricted to the server URL's origin and the main frame. `native.js` posts JSON `{id, action, ...}` and matches `{id, result}` replies; the actions are the iPhone's (`info` with `platform: 'android'`, `showGame`, `scheduleGame`, `removeGame`, `enableAlerts`, `setAlertTeams`, `haptic`) plus `openSettings` (versionCode 9 on, `info.openSettings`): the app's notification settings. From versionCode 9 `showGame`/`scheduleGame` answer `{ok: false, reason: 'notifications'}` when the app's notifications or its Live games category are off (`notificationsOn`), and plain `{ok: false}` for anything else; `pages.js` (`lockErrorText`, `settingsButton`) then says notifications are off with an **Open settings** button (under the card's switch, and under the alerts bell's note), or "Couldn't add it. Try again.", and clears the note when the app comes back with notifications on (`refreshNative`). Android stops showing its permission prompt after two refusals (or a dismissed prompt), so Settings is the only way back. Older APKs and the iPhone app give no reason: the old "Check that notifications are on" wording. `appPlatform()`/`inApp()` cover both apps, so the switches, alerts and `swipe.js` are on in both; `pages.js` words the card's subtitle and errors per platform (no Dynamic Island on Android). `inAndroidApp()` (user agent `PhadeScoresAndroid`) only keeps the first APK's `navigator.vibrate` haptics working.
- **Lock Screen card** = an ongoing notification (`LiveCards`, channel `live_games`, IMPORTANCE_DEFAULT with no sound so it isn't classed silent and hidden on the Lock Screen, VISIBILITY_PUBLIC). **Android 16+ (API 36): a Live Update** (promoted ongoing): Pixel's lock screen otherwise shrinks a seen notification to its icon, but a promoted one stays in full on the Lock Screen and AOD with a status bar chip. Promotion only takes standard styles (no custom layouts), so it follows the iPhone card as far as those go: each team's score as the title ("Patriots 14 🏈 · Bills 7"), the scorebug clock and the detail as the text, live football's timeouts as the sub text (it shows in the header line), and only in live football a platform `Notification.ProgressStyle` as the field (`field`: segments 10/100/10 for the end zones in team colors and the turf, `setStyledByProgress(false)`, progress = the ball's spot as the tracker icon (a drawn football), an amber point on the first-down line, logos as start/end icons). Measured on the `scores16` AVD: Android ignores segment colors when segments get short (ten 10-yard segments all came out the theme's color), so no yard lines; and the chip (`setShortCriticalText`) shows text up to about the width of "BOS 99-101" and DROPS anything wider (no ellipsis), so `chip()` names the leader ("PHI 20-10") only when `fitsChip` measures it no wider than that, else the bare score; a countdown chronometer before the start. Plus the `android.requestPromotedOngoing` extra (`NotificationCompat.EXTRA_REQUEST_PROMOTED_ONGOING`; API 36's SDK has no Builder setter; manifest has POST_PROMOTED_NOTIFICATIONS). The server still sends `progress`/`periods` (`gameProgress`, `gamePeriods` in `server/live.js`) for APKs through versionCode 6, whose bar was the game's progress; later APKs ignore them. **Before 16**: `DecoratedCustomViewStyle` with `res/layout/notification_card*.xml` (collapsed: abbreviations + score over the clock; expanded: league and status, logos over names either side of the score, the detail). Android 12+ always draws its own header (app icon and name) over custom layouts and indents them to the app name, so the expanded layout has `paddingEnd` 36dp to sit centered (measured on Android 15). Test the Live Update on the AVD `scores16` (Pixel 9, `system-images;android-36.1;google_apis_playstore;arm64-v8a`; Live Updates arrived in Android 16's later release, so not the plain `android-36` image): it shows as `PROMOTED_ONGOING` in `adb shell dumpsys notification`, in full on the Lock Screen (`adb shell locksettings set-disabled false` for a swipe lock), and as a status bar chip from the home screen. Debug builds take hand-made cards over adb with no server involved (`src/debug/.../DebugCards.java`): `adb shell am broadcast -n digital.hark.scores/.DebugCards --es card <base64 of lockScreenCard JSON with its state>` (grant POST_NOTIFICATIONS with `adb shell pm grant` first). Logos come from `TeamLogos` (ESPN logo cached at 160px in files/logos, drawn over a blurred white copy of itself for the glow; else the team-color badge). The card JSON is `details.js` `lockScreenCard()` and the state is `server/live.js` `contentState()`, stored in `Store` (SharedPreferences) by `league:eventId`. A swiped-away card (`CardDismissedReceiver`) or an update for a card the phone no longer has tells the server to stop. Tapping a card or an alert opens `MainActivity` with a `route` extra (validated against `#/(game|team)/x/y`), which sets `location.hash` once the page is the site and fully loaded, retried every 250 ms for up to 15 s until the page answers (Capacitor's `onPageLoaded` fires only if progress is already 100 as the page finishes, which a launch can miss).
- **Pushes**: Firebase Cloud Messaging in the Phade Firebase project (`phade-f0a20`). `Push` gets the FCM token and calls the push server with `platform: 'android'` (the same endpoints as iOS); `FcmService` handles `update`/`end`/`start`/`alert` data messages and re-registers everything on a new token, and `MainActivity` re-syncs at launch. Needs `android/app/google-services.json` (gitignored; the google-services plugin applies only when it exists); without it `Push.ready()` is false and `info` says `liveActivities: false`, `alerts: 'unavailable'`. Android 13+ asks for POST_NOTIFICATIONS on the first card or alert (`MainActivity.requestNotifications`, which the bridge thread waits on).
- **Java 21 is required** (Capacitor 8 compiles for 21). Android Studio's bundled JBR here is Java 25, which Gradle 8.14 can't run on, and Homebrew's openjdk@17 is too old: `scripts/android-apk.js` uses Homebrew's `openjdk@21`. In Android Studio, set Gradle JDK to it (Settings > Build Tools > Gradle).
- `MainActivity` adds an `OnBackPressedCallback`: Back calls `webView.goBack()` while the WebView can (the SPA's pushState entries), else leaves the app. Capacitor core has no Back handling (that's `@capacitor/app`, not used).
- Edge-to-edge: Capacitor 8's built-in SystemBars (`plugins.SystemBars` in `capacitor.config.json`: `style: DARK` for light status bar icons, `initialViewportFitValueHint: cover`). On WebView 140+ it passes the system bar insets through to CSS `env(safe-area-inset-*)`, which the site already uses for the iPhone notch.
- Themes (`res/values/styles.xml`) are dark with a `#0a0a0a` window background so nothing flashes white; Android 12+ launch shows the launcher icon on near-black (`windowSplashScreen*`), older versions `@drawable/splash` (a layer-list). Haptics are `navigator.vibrate` (manifest has `VIBRATE`).

## Push server (scores.phade.app)

- `server/` (Node 22, no dependencies, ES modules sharing `espn.js`) runs as the `scores-push` container in `/opt/scores-push` on the Phade box (74.208.219.49, SSH key `~/.ssh/ionos_vps`), on Phade's `phade_default` network behind phade-nginx (`server/scores.phade.app.conf` resolves the upstream per request so phade.app never depends on it). Deploy with `npm run push:deploy`; one-time setup and the API are in `server/README.md`. Without an APNs key it runs dry and logs pushes.
- Polls each league with a card or an alert team: 5s when a watched game is live, 15s within 15 minutes of its start, 2 minutes within 6 hours, else 15 minutes (the loop ticks every second and saves `store.json` only after a fetch). Daily boards are fetched by Eastern date (the container runs `TZ=America/New_York`). Alerts fire only on a change the server itself saw (it keeps each watched game's last state, status and score in `store.json`), so restarts never send late "starting now" alerts; each device team carries `start`/`score`/`end` switches (teams stored without them mean starts and finals).
- **Testing on a Mac**: run it locally (`TZ=America/New_York PORT=8787 DATA_DIR=<scratch> node server/index.js`), point `ScoresPushServer` in `ios/App/App/Info.plist` at `http://localhost:8787` and the app at a local web server (see "Verifying in a browser"), build for the simulator. Live Activities, their push tokens and real APNs device tokens all work in the simulator; inject alerts with `xcrun simctl push <udid> digital.hark.scores payload.apns`. Put `Info.plist` back afterwards. The simulator's display sometimes freezes after Dynamic Island or Lock Screen gestures (the status-bar clock stops); `xcrun simctl shutdown` and `boot` fixes it.
